# Checkpoint Research

1. Read the newest relevant `RESEARCH_LOG.md` entries and inspect the accepted
   evidence or decision in the conversation and repository. Do not convert a
   tentative idea, failed command, or uninspected output into a result.
2. Check whether the event is consequential enough to log: a scientific choice,
   accepted result, diagnosed surprise, changed direction, passed/failed gate, or
   material reproducibility update. Skip routine code edits and status narration.
3. Resolve any material ambiguity with the user before writing, especially the
   claim, metric interpretation, or which scientific option was accepted.
4. Add one dated entry using the existing reverse-chronological style. State:
   what was decided or observed; the evidence and limitations; why it matters;
   the next consequence; and, for a dissertation experiment, the input or
   manifest, model id and revision, parameters, seed, command, commit, and output
   location available at the time.
5. Distinguish measured facts from interpretation and planned work. Preserve the
   repository's existing terminology and metric definitions. Do not duplicate an
   existing entry or maintain a second memory file.
6. Review the inserted text against the source artifacts, then show the user the
   exact entry location and any reproducibility fields that remain missing.
